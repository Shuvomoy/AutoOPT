# BnB-PEP Methodology

This reference gives a standalone construction for turning a fully specified performance-estimation problem (PEP) for a first-order method class into a default Stage 1/2 BnB-PEP local nonlinear workflow. It is intended for skill use without relying on repository-local source files.

## Scope and non-goals

Use this methodology when the instance supplies the function class, exact interpolation inequalities or explicitly labeled non-exact constraints, method equations, performance measure, initial condition, normalizations, constants, and large-scale dimension assumption.

This reference intentionally excludes global branch-and-bound implementation for ordinary workflows. Do not require Gurobi or any global nonconvex solver in default Stage 1/2 artifacts. If the user explicitly asks for BnB-PEP Stage 3, load `stage3-global-optimization.md`; a Stage 3 run is solver evidence only, while a Stage 2 solution remains a locally optimal feasible design/certificate unless separate global evidence is supplied.

## 1. Outer design problem

Let `theta` denote all method-design parameters, such as stepsizes, coefficients, or potential weights, and let `M_theta` be the corresponding method. A BnB-PEP instance is

\[
\inf_{\theta \in \Theta} \; \mathcal R(\theta),
\qquad
\mathcal R(\theta)
= \sup\{\mathcal E(\mathcal D): \mathcal D \text{ is generated by } M_\theta,
\ f \in \mathcal F,
\ \mathcal C(\mathcal D) \le 0\}.
\]

Here `D` denotes all sampled points, gradients/subgradients, function values, and auxiliary variables. Normalizations such as `x_star = 0`, `f_star = 0`, or `g_star = 0` are allowed only when justified by the function class and initial condition.

## 2. Fixed-parameter inner worst-case problem

Fix `theta`. The inner PEP is the infinite-dimensional maximization

\[
\begin{array}{ll}
\text{maximize} & \mathcal E(\mathcal D) \\
\text{subject to} & f \in \mathcal F, \\
& \text{method equations for } M_\theta, \\
& \mathcal C(\mathcal D) \le 0, \\
& \text{normalizations and graph consistency constraints.}
\end{array}
\]

The infinite-dimensional decision variable is the function. The goal of the next steps is to replace it by finitely many exact interpolation inequalities, adding any required finite witness variables, or by explicitly labeled necessary-only constraints when exact interpolation is not available.

## 3. Interpolation reduction

Choose an index set `I` containing all sampled points and reference points, for example `I = {star,0,...,N}`. Replace `f in F` by exact interpolation inequalities whenever available. Some exact rows introduce auxiliary finite witnesses; include those witnesses in the sampled data and Gramian basis as needed. When a user-supplied row is labeled necessary-only, use it only as a relaxation and state that the resulting finite PEP is not an exact interpolation certificate for the original class. A typical scalar row has form

\[
\phi_r\bigl(\{x_i,g_i,f_i\}_{i\in I};\theta\bigr) \le 0,
\qquad r \in \mathcal I.
\]

For certificate status:

- exact interpolation rows give an exact finite PEP subject to the rank and duality assumptions stated later;
- necessary-only rows enlarge the feasible set and give an upper-bound model for the original worst-case value in a maximization PEP;
- sufficient-only rows, if supplied by a user extension, give an inner or model-specific certificate unless a separate argument justifies the original-class claim.

For the retained weakly convex bounded-subgradient row, declare proper lower-semicontinuity, \(\rho>0\), the regular-subgradient convention, the subgradient bound \(B\), and the auxiliary \(C_{j,i}\) witnesses. This row is an exact finite interpolation condition under those assumptions; for \(\rho=0\), use the Lipschitz convex row instead.

After applying the retained conditions, the inner problem is finite-dimensional:

\[
\begin{array}{ll}
\text{maximize} & \text{quadratic/linear expression in sampled data} \\
\text{subject to} & \phi_r(\text{sampled data};\theta) \le 0,
\quad r\in\mathcal I, \\
& \text{method equations, initial-condition inequalities, normalizations.}
\end{array}
\]

## 4. Gramian lifting

Collect all vector-valued atoms needed to express inner products into

\[
H = [v_1 \mid \cdots \mid v_m] \in \mathbb R^{d\times m},
\qquad
G = H^\top H \in \mathbb S_+^m.
\]

Collect scalar function values and scalar auxiliary variables into `q in R^p`. Include vector-valued witnesses, such as weakly convex \(C_{j,i}\) variables, as columns of `H` whenever their norms or inner products appear. For coefficient vectors `u,w in R^m`, define

\[
u \odot w := \frac{uw^\top + wu^\top}{2},
\qquad
\langle Hu,Hw\rangle = \langle G, u\odot w\rangle,
\]

where `\langle A,B\rangle = tr(A B)` for symmetric matrices. Express every point, gradient, and auxiliary vector as `H` times a coefficient vector, possibly depending on `theta`.

If `rank(G) <= d` is the only remaining dimension restriction and the instance assumes `d >= m`, then the rank constraint is vacuous and the Gramian formulation is an SDP. If `d < m`, dropping the rank constraint is a relaxation and must be labeled as such.

## 5. Primal SDP template for fixed parameters

For fixed `theta`, write the Gramian PEP in the standard maximization form

\[
\begin{array}{ll}
\text{maximize}_{G,q} & \langle D(\theta),G\rangle + d(\theta)^\top q + c(\theta) \\
\text{subject to} & \langle A_r(\theta),G\rangle + a_r(\theta)^\top q \le b_r(\theta),
\quad r\in\mathcal I, \\
& \langle B_s(\theta),G\rangle + b_s(\theta)^\top q = \beta_s(\theta),
\quad s\in\mathcal J, \\
& G \succeq 0.
\end{array}
\]

Inequalities include exact interpolation inequalities, explicitly labeled necessary-only constraints, and initial-condition constraints. Equalities include normalizations, exact method identities, or primitive graph identities not already built into coefficient vectors.

## 6. Dual SDP template and strong-duality posture

The corresponding dual has nonnegative multipliers `lambda_r >= 0` for inequalities, free multipliers `y_s` for equalities, and a PSD slack matrix `Z`:

\[
\begin{array}{ll}
\text{minimize}_{\lambda,y,Z} & \sum_{r\in\mathcal I}\lambda_r b_r(\theta)
+ \sum_{s\in\mathcal J} y_s \beta_s(\theta) + c(\theta) \\
\text{subject to} &
\sum_{r\in\mathcal I}\lambda_r a_r(\theta)
+ \sum_{s\in\mathcal J}y_s b_s(\theta) = d(\theta), \\
&
\sum_{r\in\mathcal I}\lambda_r A_r(\theta)
+ \sum_{s\in\mathcal J}y_s B_s(\theta) - D(\theta) = Z, \\
& Z\succeq 0,
\qquad \lambda_r\ge 0 \quad(r\in\mathcal I).
\end{array}
\]

Weak duality always gives an upper certificate on the fixed-parameter worst-case value. Equality with the primal PEP value requires strong duality. In generated derivations, either prove a suitable regularity condition such as Slater feasibility or state strong duality as an assumption/genericity posture. Without strong duality, the outer design minimizes the dual certificate `overline R(theta)`, not necessarily the exact value `R(theta)`.

## 7. Cholesky conversion to the Stage 2 local problem

Combine the outer minimization over `theta` with the fixed-parameter dual SDP. Replace the PSD constraint by the exact quadratic characterization (Horn and Johnson, *Matrix Analysis*, Corollary 7.2.9; this is the statement that generated derivations cite as Lemma `Lem:quadratic-characterization-psd-1`)

\[
Z\succeq 0
\quad\Longleftrightarrow\quad
Z = PP^\top,
\qquad
P \text{ lower triangular},
\qquad
P_{ii}\ge 0.
\]

In indices, for `n = dim(Z)`, impose

\[
P_{ij}=0 \quad (i<j),
\qquad
P_{ii}\ge 0,
\qquad
Z_{ij}=\sum_{k=1}^{\min\{i,j\}} P_{ik}P_{jk}
\quad (1\le j\le i\le n).
\]

The Stage 2 local design problem is therefore

\[
\begin{array}{ll}
\text{minimize}_{\theta,\lambda,y,Z,P} &
\sum_{r}\lambda_r b_r(\theta)+\sum_s y_s\beta_s(\theta)+c(\theta) \\
\text{subject to} & \text{dual scalar equalities}, \\
& \text{dual matrix equality defining } Z, \\
& Z=PP^\top,
\quad P \text{ lower triangular},
\quad P_{ii}\ge0, \\
& \lambda\ge0,
\quad \theta\in\Theta.
\end{array}
\]

If terms above are cubic or trilinear, either model them directly with a local nonlinear solver that supports higher-degree expressions, or introduce auxiliary variables so that every nonlinear constraint is quadratic or bilinear. Call the direct formulation a local NLP, and reserve QCQP terminology for the quadratic or bilinear auxiliary formulation. For example, replace `lambda * theta_i * theta_j` by an auxiliary `w_ij = theta_i theta_j` and a bilinear term `lambda * w_ij`, together with the defining quadratic constraint for `w_ij`.

## 8. Stage 1/2 local workflow

Stage 1 computes a feasible point for the Stage 2 local nonlinear design problem. Fix `theta = theta_init` and solve the convex dual SDP. Factor the returned `Z` as `P P^T` using Cholesky or pivoted/eigenvalue-corrected Cholesky, respecting numerical tolerances. This gives warm-start values for the inner-dual variables and `P`.

Stage 2 solves the local nonlinear design problem, warm-started from Stage 1, using a local nonlinear solver such as Ipopt or KNITRO. The output is a locally optimal feasible method/certificate. Validate by checking dual equality residuals, nonnegativity of multipliers, `||Z-PP^T||`, and by re-solving the fixed-parameter primal/dual SDPs at the returned `theta` for smoke-test horizons `N = 1,2,3,4,5`.

## 9. Canonical example: gradient-norm reduction over smooth strongly convex functions

This example uses the direct interpolation formula for smooth strongly convex functions. It does not transform `f` into a shifted smooth convex function. The Julia snippets are intentionally compact reference code: they show the mathematical objects in executable form, but omit production features such as sparsification, polishing, artificial bounds, global search, and solver-specific tuning.

### Instance

Assume `0 <= mu < L < infinity`, `R > 0`, and `N >= 1`. Let `F_{mu,L}` be the class of differentiable functions that are `mu`-strongly convex and `L`-smooth and have a minimizer `x_star`. The goal is to design a fixed-step first-order method minimizing

\[
\mathcal E = \|\nabla f(x_N)\|^2
\]

under the initial condition `||x_0-x_star||^2 <= R^2`. Normalize

\[
x_\star=0,
\qquad
f_\star=f(x_\star)=0,
\qquad
g_\star=\nabla f(x_\star)=0.
\]

Use the direct method parameterization

\[
x_i=x_0-\frac1L\sum_{j=0}^{i-1}\alpha_{i,j}g_j,
\qquad
g_j=\nabla f(x_j),
\qquad
i=1,\ldots,N.
\]

The design variables are the coefficients `alpha_{i,j}`, which are free signed reals: the BnB-PEP design space does not restrict their sign, and the source reference implementations likewise default to free stepsizes. Impose sign or interval constraints only if the user's method class explicitly requires them, and document any such restriction in the derivation. If the user supplies raw update coefficients `c_{i,j}` in `x_i = x_{i-1} - sum_j c_{i,j} g_j` without a `1/L` factor, set `h_{i,j} = L * c_{i,j}` so that the `1/L`-scaled parameterizations used here match the user's method. If one starts from incremental coefficients `h` in

\[
x_i=x_{i-1}-\frac1L\sum_{j=0}^{i-1}h_{i,j}g_j,
\]

then the above coefficients satisfy

\[
\alpha_{i,i-1}=h_{i,i-1},
\qquad
\alpha_{i,j}=\alpha_{i-1,j}+h_{i,j}
\quad (0\le j\le i-2),
\]

and the inverse relations are `h_{i,i-1}=alpha_{i,i-1}` and `h_{i,j}=alpha_{i,j}-alpha_{i-1,j}`.

### Interpolation and finite-dimensional PEP

Let `I_N^star = {star,0,1,...,N}`. For `f in F_{mu,L}`, exact smooth strongly convex interpolation is

\[
f_i \ge f_j + \langle g_j,x_i-x_j\rangle
+ \frac{1}{2(1-\mu/L)}
\left(
\frac1L\|g_i-g_j\|^2
+\mu\|x_i-x_j\|^2
-2\frac{\mu}{L}\langle g_i-g_j,x_i-x_j\rangle
\right),
\]

for all distinct `i,j in I_N^star`. This is the expanded form of the completed-square row for `(mu,L)`-smooth strongly convex functions in `references/interpolation-conditions.md`: expanding the squared norm `\|x_i-x_j-(1/L)(g_i-g_j)\|^2` there and collecting terms yields exactly the bracketed expression above, so the two statements are interchangeable. Therefore, for fixed `alpha`, the inner PEP is the finite-dimensional maximization over `x_i,g_i,f_i`:

\[
\begin{array}{ll}
\text{maximize} & \|g_N\|^2 \\
\text{subject to} & \text{the interpolation inequalities above for } i\ne j, \\
& x_i=x_0-\frac1L\sum_{j=0}^{i-1}\alpha_{i,j}g_j,
\quad i=1,\ldots,N,\\
& \|x_0\|^2\le R^2,\\
& x_\star=0,
\quad f_\star=0,
\quad g_\star=0.
\end{array}
\]

### Gramian data

Let

\[
H=[x_0\mid g_0\mid g_1\mid\cdots\mid g_N]\in\mathbb R^{d\times(N+2)},
\qquad
G=H^\top H,
\qquad
F=[f_0\mid f_1\mid\cdots\mid f_N].
\]

Assume the large-scale condition `d >= N+2`, so the rank constraint on `G` is vacuous. Define coefficient vectors in `R^{N+2}` and `R^{N+1}` by

\[
\mathbf x_0=e_1,
\quad
\mathbf x_\star=0,
\quad
\mathbf g_\star=0,
\quad
\mathbf g_i=e_{i+2}\quad(0\le i\le N),
\]

\[
\mathbf x_i
=\mathbf x_0-\frac1L\sum_{j=0}^{i-1}\alpha_{i,j}\mathbf g_j,
\qquad i=1,\ldots,N,
\]

\[
\mathbf f_\star=0,
\qquad
\mathbf f_i=e_{i+1}\quad(0\le i\le N).
\]

Then `x_i=H x_i_bold`, `g_i=H g_i_bold`, and `f_i=F f_i_bold`. Here `u odot v = (uv^T+vu^T)/2`. For each ordered pair `i,j in I_N^star` with `i != j`, the matrix multiplying `G` in the interpolation inequality is written directly as

\[
\mathbf g_j\odot(\mathbf x_i-\mathbf x_j)
+ \frac{1}{2(1-\mu/L)}
\left(
\frac1L(\mathbf g_i-\mathbf g_j)\odot(\mathbf g_i-\mathbf g_j)
+\mu(\mathbf x_i-\mathbf x_j)\odot(\mathbf x_i-\mathbf x_j)
-2\frac{\mu}{L}(\mathbf g_i-\mathbf g_j)\odot(\mathbf x_i-\mathbf x_j)
\right),
\]

and the vector multiplying `F` is `\mathbf f_j-\mathbf f_i`. The objective matrix is written directly as `(\mathbf g_N-\mathbf g_\star)\odot(\mathbf g_N-\mathbf g_\star)`, since

\[
\left\langle G,(\mathbf g_N-\mathbf g_\star)\odot(\mathbf g_N-\mathbf g_\star)\right\rangle
=\|g_N-g_\star\|^2=\|g_N\|^2.
\]

```julia
function e_i(n::Integer, i::Integer)
    v = zeros(Float64, n)
    v[i] = 1.0
    return v
end

⊙(u, v) = 0.5 .* (u * v' + v * u')
⊙(u) = u * u'

function default_alpha(N::Integer)
    α = OffsetArray(zeros(Float64, N, N), 1:N, 0:N-1)
    for i in 1:N, j in 0:i-1
        α[i, j] = 1.0
    end
    return α
end

function data_generator_function(N::Integer, α, μ::Real, L::Real)
    # μ is part of the instance data and is kept in the signature for
    # uniformity across function classes; this particular generator does not
    # use it because the interpolation matrices are assembled by the callers.
    dim_G = N + 2
    dim_F = N + 1

    g_cols = Vector{Any}(undef, N + 2)
    g_cols[1] = zeros(Float64, dim_G)
    for i in 0:N
        g_cols[i + 2] = e_i(dim_G, i + 2)
    end

    x_cols = Vector{Any}(undef, N + 2)
    x_cols[1] = zeros(Float64, dim_G)
    x_cols[2] = e_i(dim_G, 1)
    for i in 1:N
        xi = e_i(dim_G, 1)
        for j in 0:i-1
            xi = xi .- (α[i, j] / L) .* e_i(dim_G, j + 2)
        end
        x_cols[i + 2] = xi
    end

    f_cols = Vector{Any}(undef, N + 2)
    f_cols[1] = zeros(Float64, dim_F)
    for i in 0:N
        f_cols[i + 2] = e_i(dim_F, i + 1)
    end

    return (
        x_coef = OffsetArray(hcat(x_cols...), 1:dim_G, -1:N),
        g_coef = OffsetArray(hcat(g_cols...), 1:dim_G, -1:N),
        f_coef = OffsetArray(hcat(f_cols...), 1:dim_F, -1:N),
    )
end
```

### Primal SDP for fixed `alpha`

For fixed `alpha`, the inner PEP is the SDP

\[
\begin{array}{ll}
\text{maximize}_{G,F} &
\left\langle G,(\mathbf g_N-\mathbf g_\star)\odot(\mathbf g_N-\mathbf g_\star)\right\rangle \\
\text{subject to} &
\displaystyle
F(\mathbf f_j-\mathbf f_i)
+ \left\langle G,\;
\mathbf g_j\odot(\mathbf x_i-\mathbf x_j)
+ \frac{1}{2(1-\mu/L)}
\left(
\frac1L(\mathbf g_i-\mathbf g_j)\odot(\mathbf g_i-\mathbf g_j)
+\mu(\mathbf x_i-\mathbf x_j)\odot(\mathbf x_i-\mathbf x_j)
-2\frac{\mu}{L}(\mathbf g_i-\mathbf g_j)\odot(\mathbf x_i-\mathbf x_j)
\right)
\right\rangle \le 0,
\quad i,j\in I_N^\star,
\quad i\ne j, \\
& \left\langle G,(\mathbf x_0-\mathbf x_\star)\odot(\mathbf x_0-\mathbf x_\star)\right\rangle\le R^2,\\
& G\succeq0.
\end{array}
\]

```julia
function solve_primal_pep(N, μ, L, α, R; optimizer = default_sdp_optimizer(), silent = true)
    model = Model(optimizer)
    silent && set_silent(model)

    dim_G = N + 2
    dim_F = N + 1
    data = data_generator_function(N, α, μ, L)
    scale = 1 / (2 * (1 - μ / L))

    @variable(model, G[1:dim_G, 1:dim_G], PSD)
    @variable(model, F[1:dim_F])

    objective_matrix = (data.g_coef[:, N] - data.g_coef[:, -1]) ⊙
                       (data.g_coef[:, N] - data.g_coef[:, -1])
    @objective(model, Max, tr(objective_matrix * G))

    for i in -1:N, j in -1:N
        i == j && continue
        xi = data.x_coef[:, i]
        xj = data.x_coef[:, j]
        gi = data.g_coef[:, i]
        gj = data.g_coef[:, j]
        fj_minus_fi = data.f_coef[:, j] - data.f_coef[:, i]
        interp_matrix = gj ⊙ (xi - xj) +
                        scale * ((1 / L) * ((gi - gj) ⊙ (gi - gj)) +
                                 μ * ((xi - xj) ⊙ (xi - xj)) -
                                 2 * (μ / L) * ((gi - gj) ⊙ (xi - xj)))
        @constraint(model, dot(fj_minus_fi, F) + tr(interp_matrix * G) <= 0)
    end

    initial_matrix = (data.x_coef[:, 0] - data.x_coef[:, -1]) ⊙
                     (data.x_coef[:, 0] - data.x_coef[:, -1])
    @constraint(model, tr(initial_matrix * G) <= R^2)
    optimize!(model)

    return (
        status = termination_status(model),
        objective = has_values(model) ? objective_value(model) : NaN,
        G = has_values(model) ? value.(G) : nothing,
        F = has_values(model) ? value.(F) : nothing,
        α = α,
    )
end
```

### Dual SDP for fixed `alpha`

Use multipliers `lambda_{i,j} >= 0` for interpolation inequalities and `nu >= 0` for the initial condition. The fixed-parameter dual SDP is

\[
\begin{array}{ll}
\text{minimize}_{\lambda,\nu,Z} & \nu R^2 \\
\text{subject to} &
\sum_{i,j\in I_N^\star: i\ne j}\lambda_{i,j}(\mathbf f_j-\mathbf f_i)=0, \\
&
\nu(\mathbf x_0-\mathbf x_\star)\odot(\mathbf x_0-\mathbf x_\star)
-(\mathbf g_N-\mathbf g_\star)\odot(\mathbf g_N-\mathbf g_\star)\\
&\displaystyle\quad
+\sum_{i,j\in I_N^\star: i\ne j}\lambda_{i,j}
\left[
\mathbf g_j\odot(\mathbf x_i-\mathbf x_j)
+ \frac{1}{2(1-\mu/L)}
\left(
\frac1L(\mathbf g_i-\mathbf g_j)\odot(\mathbf g_i-\mathbf g_j)
+\mu(\mathbf x_i-\mathbf x_j)\odot(\mathbf x_i-\mathbf x_j)
-2\frac{\mu}{L}(\mathbf g_i-\mathbf g_j)\odot(\mathbf x_i-\mathbf x_j)
\right)
\right]=Z,\\
& Z\succeq0,
\qquad \nu\ge0,
\qquad \lambda_{i,j}\ge0.
\end{array}
\]

For this canonical smooth strongly convex interpolation SDP, strong duality is standard under the usual Slater/regularity conditions. In a generated derivation, state the condition explicitly or label the dual as an upper certificate.

```julia
function psd_factor(Z; tol = 1e-8)
    S = Symmetric(0.5 .* (Z .+ Z'))
    λmin = minimum(eigvals(S))
    jitter = max(tol, -λmin + tol)
    return Matrix(cholesky(S + jitter * I; check = false).L)
end

function solve_dual_pep(N, μ, L, α, R; optimizer = default_sdp_optimizer(), silent = true)
    model = Model(optimizer)
    silent && set_silent(model)

    dim_G = N + 2
    dim_F = N + 1
    data = data_generator_function(N, α, μ, L)
    scale = 1 / (2 * (1 - μ / L))

    @variable(model, λ[i = -1:N, j = -1:N; i != j] >= 0)
    @variable(model, ν >= 0)
    @variable(model, Z[1:dim_G, 1:dim_G], PSD)

    @objective(model, Min, ν * R^2)

    @constraint(model, [r in 1:dim_F],
        sum(λ[i, j] * (data.f_coef[:, j] - data.f_coef[:, i])[r]
            for i in -1:N for j in -1:N if i != j) == 0
    )

    initial_matrix = (data.x_coef[:, 0] - data.x_coef[:, -1]) ⊙
                     (data.x_coef[:, 0] - data.x_coef[:, -1])
    objective_matrix = (data.g_coef[:, N] - data.g_coef[:, -1]) ⊙
                       (data.g_coef[:, N] - data.g_coef[:, -1])
    dual_matrix = ν .* initial_matrix - objective_matrix
    for i in -1:N, j in -1:N
        i == j && continue
        xi = data.x_coef[:, i]
        xj = data.x_coef[:, j]
        gi = data.g_coef[:, i]
        gj = data.g_coef[:, j]
        interp_matrix = gj ⊙ (xi - xj) +
                        scale * ((1 / L) * ((gi - gj) ⊙ (gi - gj)) +
                                 μ * ((xi - xj) ⊙ (xi - xj)) -
                                 2 * (μ / L) * ((gi - gj) ⊙ (xi - xj)))
        dual_matrix = dual_matrix .+ λ[i, j] .* interp_matrix
    end
    @constraint(model, [p in 1:dim_G, q in 1:dim_G], dual_matrix[p, q] == Z[p, q])

    optimize!(model)
    Z_val = has_values(model) ? value.(Z) : nothing

    return (
        status = termination_status(model),
        objective = has_values(model) ? objective_value(model) : NaN,
        λ = has_values(model) ? value.(λ) : nothing,
        ν = has_values(model) ? value(ν) : NaN,
        Z = Z_val,
        P = Z_val === nothing ? nothing : psd_factor(Z_val),
        α = α,
    )
end
```

### Direct cubic BnB-PEP local model for the example

The outer problem optimizes over `alpha` and the fixed-parameter dual variables. The term `lambda_{i,j}((\mathbf x_i-\mathbf x_j)\odot(\mathbf x_i-\mathbf x_j))` is cubic because each `\mathbf x_i` is affine in `alpha`. Some local nonlinear solvers can model this term directly, so this embedded example uses the direct cubic local NLP rather than introducing auxiliary matrices. A quadratic or bilinear auxiliary formulation may instead be called a QCQP.

The Stage 2 direct cubic local NLP is

\[
\begin{array}{ll}
\text{minimize} & \nu R^2 \\
\text{subject to} &
\sum_{i,j\in I_N^\star: i\ne j}\lambda_{i,j}(\mathbf f_j-\mathbf f_i)=0,\\
&
\nu(\mathbf x_0-\mathbf x_\star)\odot(\mathbf x_0-\mathbf x_\star)
-(\mathbf g_N-\mathbf g_\star)\odot(\mathbf g_N-\mathbf g_\star)\\
&\displaystyle\quad
+\sum_{i,j\in I_N^\star: i\ne j}\lambda_{i,j}
\left[
\mathbf g_j\odot(\mathbf x_i-\mathbf x_j)
+ \frac{1}{2(1-\mu/L)}
\left(
\frac1L(\mathbf g_i-\mathbf g_j)\odot(\mathbf g_i-\mathbf g_j)
+\mu(\mathbf x_i-\mathbf x_j)\odot(\mathbf x_i-\mathbf x_j)
-2\frac{\mu}{L}(\mathbf g_i-\mathbf g_j)\odot(\mathbf x_i-\mathbf x_j)
\right)
\right]=Z,\\
& Z=PP^\top,
\quad P \text{ lower triangular},
\quad P_{ii}\ge0,\\
& \nu\ge0,
\quad \lambda_{i,j}\ge0,
\quad \alpha_{i,j}\in\mathbb R.
\end{array}
\]

The matrix equality contains cubic terms from `lambda * ((x_i-x_j) odot (x_i-x_j))`, and the Cholesky equality `Z=P P^T` is quadratic. This direct formulation is a local NLP and certifies only the local solve returned by the nonlinear optimizer.

```julia
function solve_bnb_pep(N, μ, L, R, warm; optimizer = default_local_optimizer(), silent = true)
    if warm.λ === nothing || warm.Z === nothing || warm.P === nothing
        # Stage 1 did not return a usable certificate; fail gracefully instead
        # of erroring inside the warm-start loops.
        return (status = :stage1_warm_start_missing, objective = NaN,
                λ = nothing, ν = NaN, Z = nothing, P = nothing, α = nothing)
    end

    model = Model(optimizer)
    silent && set_silent(model)

    dim_G = N + 2
    dim_F = N + 1
    scale = 1 / (2 * (1 - μ / L))
    matrix_shape = SymmetricMatrixShape(dim_G)
    @variable(model, λ[i = -1:N, j = -1:N; i != j] >= 0)
    @variable(model, ν >= 0)
    @variable(model, Z[1:dim_G, 1:dim_G], Symmetric)
    @variable(model, P[1:dim_G, 1:dim_G])
    # Free signed coefficients: the BnB-PEP design space does not restrict the
    # sign of α, and the source reference code defaults to free stepsizes. Add
    # bounds here only if the intended method class requires them.
    @variable(model, α[i = 1:N, j = 0:i-1])

    for i in -1:N, j in -1:N
        i == j && continue
        set_start_value(λ[i, j], max(0.0, warm.λ[i, j]))
    end
    set_start_value(ν, max(0.0, warm.ν))
    for i in 1:N, j in 0:i-1
        set_start_value(α[i, j], warm.α[i, j])
    end
    for p in 1:dim_G, q in 1:dim_G
        set_start_value(Z[p, q], warm.Z[p, q])
        set_start_value(P[p, q], warm.P[p, q])
    end

    data = data_generator_function(N, α, μ, L)
    @objective(model, Min, ν * R^2)

    @constraint(model, [r in 1:dim_F],
        sum(λ[i, j] * (data.f_coef[:, j] - data.f_coef[:, i])[r]
            for i in -1:N for j in -1:N if i != j) == 0
    )

    initial_matrix = (data.x_coef[:, 0] - data.x_coef[:, -1]) ⊙
                     (data.x_coef[:, 0] - data.x_coef[:, -1])
    objective_matrix = (data.g_coef[:, N] - data.g_coef[:, -1]) ⊙
                       (data.g_coef[:, N] - data.g_coef[:, -1])
    dual_matrix = ν .* initial_matrix - objective_matrix
    for i in -1:N, j in -1:N
        i == j && continue
        xi = data.x_coef[:, i]
        xj = data.x_coef[:, j]
        gi = data.g_coef[:, i]
        gj = data.g_coef[:, j]
        interp_matrix = gj ⊙ (xi - xj) +
                        scale * ((1 / L) * ((gi - gj) ⊙ (gi - gj)) +
                                 μ * ((xi - xj) ⊙ (xi - xj)) -
                                 2 * (μ / L) * ((gi - gj) ⊙ (xi - xj)))
        dual_matrix = dual_matrix .+ λ[i, j] .* interp_matrix
    end
    @constraint(model, vectorize(dual_matrix - Z, matrix_shape) .== 0)

    @constraint(model, [p = 1:dim_G, q = p+1:dim_G], P[p, q] == 0)
    @constraint(model, [p in 1:dim_G], P[p, p] >= 0)
    @constraint(model, vectorize(Z - P * P', matrix_shape) .== 0)

    optimize!(model)

    return (
        status = termination_status(model),
        objective = has_values(model) ? objective_value(model) : NaN,
        λ = has_values(model) ? value.(λ) : nothing,
        ν = has_values(model) ? value(ν) : NaN,
        Z = has_values(model) ? value.(Z) : nothing,
        P = has_values(model) ? value.(P) : nothing,
        α = has_values(model) ? value.(α) : nothing,
    )
end
```

For Stage 1, initialize with a simple gradient-descent method, for example incremental coefficients `h_{i,i-1}=1` and `h_{i,j}=0` for `j<i-1`, which corresponds to `alpha_{i,j}=1` for all `j<i`. Fix this `alpha`, solve the convex dual SDP, and factor the resulting `Z` as `P P^T`. The `solve_dual_pep` function returns a `NamedTuple` that is used directly as the Stage 2 warm-start object. For Stage 2, warm-start the direct cubic local model with this dual/Cholesky point and solve locally with the selected local optimizer. The one-horizon helper below checks dual residuals, nonnegativity of multipliers, `||Z-P P^T||`, and primal/dual agreement for the returned fixed `alpha`; generated artifacts should call it over horizons `N = 1,2,3,4,5`.

```julia
function status_in(result, accepted_statuses)
    return result !== nothing && string(result.status) in accepted_statuses
end

function objective_gap(left, right)
    if left === nothing || right === nothing
        return Inf
    end
    if !isfinite(left.objective) || !isfinite(right.objective)
        return Inf
    end
    return abs(left.objective - right.objective)
end

function dual_certificate_residuals(N, μ, L, R, certificate)
    dim_G = N + 2
    dim_F = N + 1
    if certificate.λ === nothing || certificate.Z === nothing ||
       certificate.P === nothing || certificate.α === nothing ||
       !isfinite(certificate.ν)
        return (
            scalar_residual = Inf,
            matrix_residual = Inf,
            cholesky_residual = Inf,
            upper_triangular_residual = Inf,
            min_lambda = -Inf,
            min_diag_P = -Inf,
        )
    end

    data = data_generator_function(N, certificate.α, μ, L)
    scale = 1 / (2 * (1 - μ / L))

    scalar_residual = zeros(Float64, dim_F)
    for i in -1:N, j in -1:N
        i == j && continue
        scalar_residual .+= certificate.λ[i, j] .* (data.f_coef[:, j] - data.f_coef[:, i])
    end

    initial_matrix = (data.x_coef[:, 0] - data.x_coef[:, -1]) ⊙
                     (data.x_coef[:, 0] - data.x_coef[:, -1])
    objective_matrix = (data.g_coef[:, N] - data.g_coef[:, -1]) ⊙
                       (data.g_coef[:, N] - data.g_coef[:, -1])
    dual_matrix = certificate.ν .* initial_matrix - objective_matrix
    for i in -1:N, j in -1:N
        i == j && continue
        xi = data.x_coef[:, i]
        xj = data.x_coef[:, j]
        gi = data.g_coef[:, i]
        gj = data.g_coef[:, j]
        interp_matrix = gj ⊙ (xi - xj) +
                        scale * ((1 / L) * ((gi - gj) ⊙ (gi - gj)) +
                                 μ * ((xi - xj) ⊙ (xi - xj)) -
                                 2 * (μ / L) * ((gi - gj) ⊙ (xi - xj)))
        dual_matrix = dual_matrix .+ certificate.λ[i, j] .* interp_matrix
    end

    return (
        scalar_residual = norm(scalar_residual, Inf),
        matrix_residual = norm(dual_matrix - certificate.Z, Inf),
        cholesky_residual = norm(certificate.Z - certificate.P * certificate.P', Inf),
        upper_triangular_residual = maximum(abs(certificate.P[p, q])
                                            for p in 1:dim_G for q in p+1:dim_G),
        min_lambda = minimum(certificate.λ[i, j]
                             for i in -1:N for j in -1:N if i != j),
        min_diag_P = minimum(certificate.P[p, p] for p in 1:dim_G),
    )
end

function stage1_stage2_demo(; N = 2, μ = 0.1, L = 1.0, R = 1.0, tol = 1e-5)
    @assert N <= 5 "Use this embedded demo only for smoke-test horizons N = 1,2,3,4,5."
    α0 = default_alpha(N)
    primal = solve_primal_pep(N, μ, L, α0, R)
    stage1 = solve_dual_pep(N, μ, L, α0, R)
    stage2 = solve_bnb_pep(N, μ, L, R, stage1)

    returned_primal = stage2.α === nothing ? nothing : solve_primal_pep(N, μ, L, stage2.α, R)
    returned_dual = stage2.α === nothing ? nothing : solve_dual_pep(N, μ, L, stage2.α, R)
    stage1_residuals = dual_certificate_residuals(N, μ, L, R, stage1)
    stage2_residuals = dual_certificate_residuals(N, μ, L, R, stage2)
    fixed_alpha_gap = objective_gap(returned_primal, returned_dual)

    checks = (
        # ALMOST_* statuses are accepted with reduced confidence: some conic
        # solvers (for example Clarabel) report them for usable borderline
        # solves; report the exact status alongside the boolean checks.
        initial_primal_sdp_solved = status_in(primal, ("OPTIMAL", "ALMOST_OPTIMAL")),
        stage1_dual_sdp_solved = status_in(stage1, ("OPTIMAL", "ALMOST_OPTIMAL")),
        # Historical umbrella name for the Stage 2 local-solve check. It does
        # not imply the direct cubic model is literally a QCQP unless auxiliary
        # variables are introduced to obtain a quadratic/bilinear formulation.
        stage2_local_qcqp_solved = status_in(stage2, ("LOCALLY_SOLVED", "ALMOST_LOCALLY_SOLVED", "OPTIMAL")),
        stage1_dual_residual_ok = stage1_residuals.scalar_residual <= tol &&
                                  stage1_residuals.matrix_residual <= tol,
        stage2_dual_residual_ok = stage2_residuals.scalar_residual <= tol &&
                                  stage2_residuals.matrix_residual <= tol,
        stage2_cholesky_ok = stage2_residuals.cholesky_residual <= tol &&
                             stage2_residuals.upper_triangular_residual <= tol &&
                             stage2_residuals.min_diag_P >= -tol,
        stage2_multipliers_nonnegative = stage2_residuals.min_lambda >= -tol,
        returned_fixed_alpha_primal_dual_gap_ok = fixed_alpha_gap <= tol,
    )

    validation = (
        stage1_residuals = stage1_residuals,
        stage2_residuals = stage2_residuals,
        returned_fixed_alpha_gap = fixed_alpha_gap,
        checks = checks,
        all_checks_passed = all(values(checks)),
    )

    return (
        primal = primal,
        stage1 = stage1,
        stage2 = stage2,
        returned_primal = returned_primal,
        returned_dual = returned_dual,
        validation = validation,
    )
end
```

## 10. Checklist for new instances

Before deriving or coding a new BnB-PEP instance, verify the following:

1. The retained conditions are exact interpolation rows, or any necessary-only/sufficient-only status is explicitly labeled with the corresponding certificate direction.
2. All method equations are encoded either in coefficient vectors or explicit constraints.
3. Every inner product is represented by a Gramian entry.
4. The dimension assumption makes the Gramian rank constraint vacuous, or else the relaxation is stated.
5. The primal SDP and dual SDP are written for fixed method parameters before optimizing over them.
6. Strong duality is proved, assumed, or the result is described only as a dual certificate.
7. The PSD slack is replaced by `Z=PP^T` with lower-triangular `P` and nonnegative diagonal.
8. Cubic/trilinear terms are either modeled directly by a compatible local nonlinear solver or converted to quadratic/bilinear form with auxiliary variables.
9. Stage 1 fixes method parameters and solves a convex SDP.
10. Stage 2 solves only a local nonlinear problem and never claims global optimality.
